# Architecture

## Decisions

| Topic | Choice | Why (alternatives considered) |
|---|---|---|
| Framework | **Astro 7 (static output), TypeScript strict** | Content site with a few interactive islands. Astro ships zero JavaScript by default (home, guide, FAQ pages weigh 14–52 KB), produces plain static files (any host, no server), has first-class i18n routing and Markdown content collections. Next.js was evaluated: it would bring React and a server/edge runtime that the project does not need. |
| UI | Plain CSS with design tokens, logical properties for RTL | No framework needed for the size of the site; logical properties (`margin-inline`, `inset-inline-start`) make Arabic RTL work without duplicated styles. Tailwind would add a build dependency without clear benefit here. |
| Interactivity | Vanilla TypeScript modules bundled by Vite | Calculator, simulation and map do not need React. |
| Map engine | **MapLibre GL JS 6** + **OpenFreeMap** vector tiles | Vector tiles render sharply at every zoom, labels in the page language (`name:fr`, `name:ar`, `name:en`), Arabic shaping via the RTL text plugin, smooth on mobile. OpenFreeMap is free, without API key or usage quota. Leaflet was evaluated: lighter (≈ 40 KB) but raster tiles from openstreetmap.org are not allowed for heavy production use, and commercial tile providers need keys and paid plans. The cost of MapLibre (~280 KB gzipped) is paid only on the map page, where it is loaded lazily. |
| Astronomy | **Own engine on NASA's Besselian elements** (`src/lib/eclipse`) | Same model as NASA's predictions, a few KB, runs in the browser for any point. Validated against NASA's tables and against Astronomy Engine (independent ephemerides). |
| Geographic data | Static GeoJSON (≈ 250 KB in total), EPSG:4326 | Data volume is tiny and fixed. PostGIS or vector tiles would add a server and costs without any functional need. |
| Content | Markdown content collections + typed data files | Pages and news can be edited without touching code; translations sit side by side (`src/content/pages/{en,fr,ar}`). |
| Hosting | Static hosting (GitHub Pages or Cloudflare Pages) | See [DEPLOYMENT.md](DEPLOYMENT.md). |

## Layers

```
data (JSON/GeoJSON, Markdown)  →  logic (src/lib: eclipse engine, data, validation, format)  →  UI (components, pages, scripts)
```

- `src/lib/eclipse/` has no dependency on the UI, Astro or the DOM: it is used at build time (tables, key figures, validation) and in the browser (calculator, map, simulation).
- `src/lib/data.ts` joins places, destinations and climate with computed circumstances at build time.
- `src/scripts/` contains browser-only code; localized strings reach it through a JSON block (`components/ClientI18n.astro`).

## Internationalisation

- Locales `en`, `fr`, `ar`; every URL is prefixed (`/en/…`, `/fr/…`, `/ar/…`); the root `/` is a language chooser (`x-default`).
- Path segments are identical across languages (`/fr/map/`, `/ar/map/`) to keep the language switcher, hreflang and maintenance simple.
- UI strings: `src/i18n/ui.ts` — the French and Arabic dictionaries are typed against the English one, so a missing key fails the type check.
- Arabic: `dir="rtl"`, Arabic font stack, Western digits (`ar-TN-u-nu-latn`, usual in Tunisia), Maghreb month names (أوت), map labels shaped by the RTL text plugin.
- Dates and numbers use `Intl` with the locale of the page; coordinates use the technical notation (decimal point) in every language.

## SEO

Unique title and description per page and language, canonical URLs, `hreflang` (+ `x-default`), XML sitemap with alternates, `robots.txt`, Open Graph/Twitter cards with a 1200×630 image per language, structured data (`WebSite`, `Event`, `Article`, `FAQPage`, `NewsArticle`, `TouristDestination`), one `h1` per page, descriptive URLs. All checked by the end-to-end tests.

## Security and privacy

- Static site: no server code, no database, no form, no account, no cookies.
- Content-Security-Policy generated by Astro with hashes of the inline scripts and styles; external connections limited to `tiles.openfreemap.org` (and the analytics origin if one is configured).
- `public/_headers` adds HSTS, `nosniff`, `Referrer-Policy`, `Permissions-Policy` (geolocation only for the site itself), `X-Frame-Options` on hosts that support it (Cloudflare Pages, Netlify). GitHub Pages does not support custom headers; the CSP is still applied through the `<meta>` tag.
- Geolocation only on an explicit click; the position never leaves the browser.
- User input (coordinates) is parsed and range-checked; every value inserted into HTML is escaped.
- No secret in the repository; configuration via environment variables / repository variables.

## Performance

- Pages other than the map: 14–52 KB transferred, Lighthouse 100/100/100/100 (mobile profile, measured locally).
- Map page: MapLibre loaded after the panel and results are interactive; GeoJSON layers ≈ 250 KB, cached; if the background map fails, the eclipse layers still work.
- No web fonts (system fonts), images generated at the right size, long cache for hashed assets.
